# Navert多协议通信转发仪

基于STM32F407VET6的多协议通信转发仪，把USART1/2、CAN1/2、I²C1/2、SPI2/3共8个通信口接进来，按端口配置转发去向，任意口可以转发到任意口，使用LVGL配合LCD屏幕实现实时收发监视、在线参数配置、一键开关转发。

> - **操作指南**：[Doc/STEP.md](Doc/STEP.md)：从零上手指南（硬件连接、软件配置、功能验证）；[Doc/STRUCTURE.md](Doc/STRUCTURE.md)（工程、项目结构）；[Doc/STREAM.md](Doc/STREAM.md)（数据流向）。

## 😶‍🌫️项目概述

本项目是基于STM32F407VET6的多协议通信转发仪：八路不同通信协议的数据全部打包成统一消息进队列，靠一张路由表决定去向，所有参数（波特率、CAN帧ID、I²C地址、SPI速率）都在屏幕上改，改完立即生效，不用重新烧写固件。

### 核心功能

- **八路收发**：CAN1/2、USART1/2、IIC1/2、SPI2/3，支持任意两个端口间收发
- **灵活路由**：按来源端口配置目标端口，支持多路汇聚到同一个口；一键Start Forward/Stop Forward
- **协议互转**：跨协议转发时自动封装目标协议需要的帧头（把数据按协议打包）
- **在线配置**：串口（波特率/字长/停止位/校验）、CAN（波特率/转发ID/标准帧扩展帧/掩码）、I²C（速率/从机地址，主从自动切换）、SPI（主从/CPOL/CPHA/字长/分频）
- **人机交互**：LCD(ST7789)触摸屏，LVGL友好界面

## 🥇项目亮点

以下是一些本项目值得关注的亮点（或许）：

### 1. 统一消息格式，把协议和转发彻底解耦

```c
//任何协议收上来的消息都解包数据然后打包成Msg再进缓冲区
typedef struct {
	Src_t    src;          //从哪个口来的
	uint16_t len;          //实际长度
	uint8_t  data[256];    //内容
} Msg_t;

本项目主要是为了不同协议间消息转发，因此消息里数据是最重要的，协议帧的规定比如CAN的ID只是辅助Navert接收消息，
所以在放入缓冲区的时候只打包CAN帧包含的信息，在转发层按照目标端口协议重新打包好发送出去

```

### 2. 每个协议接收完成的判断

| 协议 | 帧边界靠什么 | 长度从哪来 |
|------|--------------|------------|
| USART | IDLE空闲中断/DMA收满 | 回调传进来的Size |
| CAN | 硬件自主完成 | DLC |
| I²C从机 | 主机发STOP，或收满256字节 | pBuffPtr-rx_buf指针偏移 |
| SPI从机 | 主循环轮询BSY标志，连续为0才算一帧结束 | SPI_RX_BUF_SIZE-NDTR |

SPI从机最特殊：**没有IDLE这类事件可用**，只能靠SPI_RT_Poll()在主循环里轮询BSY，所以它被排在Transfer_Poll()的第一位，每次先判断是否收完

### 3. 非阻塞式设计：只能中断写，主循环读

- **中断/DMA上下文**：接收消息并封装成Msg放入缓冲区
- **主循环上下文**：从缓冲区读取消息并转发

### 4. 每类协议一个环形缓冲

```c
//单生产者单消费者：head只由中断推进，tail只由主循环推进，不需要临界区
int RingBuf_Write(RingBuf_t *rb, const Msg_t *msg);
int RingBuf_Read(RingBuf_t *rb, Msg_t *msg);
```

环形缓冲满与空：牺牲一个槽位，如果有N个槽位，head是写位置，tail是读位置，当**head == tail**时，认定缓冲区空，当(head + 1) % N == tail时，认定缓冲区满

- **独立**：一个协议写满只丢自己的数据，别的协议照常收发
- **缺点**：为每个协议分配全局缓冲区占RAM多

### 5. tx_busy+hold双重保证不丢包

转发时才发现目标口还在发上一帧（DMA没完成），这时候数据已经从环形缓冲里取出来了：
此时不能放回环形缓冲区，因为写缓冲只能由接收中断完成，主循环只能读缓冲，也不能丢掉消息，
所以给每类协议留了一个hold槽暂存，下一轮Transfer_TryHeld()开头重试。**深度只有1**，因为它的意义只是忙时暂存消息，真正的缓冲在环形缓冲里还有31帧。tx_busy由发送完成回调清零，因为Send()返回OK只代表DMA开始搬运了，不代表发完了。

### 6. 参数在线改，改完立即生效

- **串口**：DeInit→改参数→Init→重启接收
- **CAN**：预分频+BS1/BS2组合算出波特率，界面直接显示Bit Rate: 250kbps这样的实际值
- **I²C**：主机100kHz/400kHz、从机地址可换，模式切换前后按需开关中断
- **SPI**：分频从/2到/256，界面实时显示SPI Freq: 21MHz等

### 7. 分层与模块化

- **解耦**：Transfer.c只管转发、RingBuf.c只管缓冲、ui.c只管界面，互不越界，模块内部函数变量用static限制作用域，只留统一接口给应用层
- **分层**：CubeMX的东西全部在Core/，自己的代码写在User/，重新生成配置不会覆盖自己的代码
- **模块化**：除统一Msg消息格式外，每个模块单独Cfg配置结构体，对应用层只展示API

### 8. SPI主从模式切换

SPI通信的本质是数据交换，但是本项目把SPI模式抽象成单向收发，因为通信转发的时候从某种协议接收肯定不能按原协议发回，
所以SPI单次转发只被用来接收或者发送

- **主机**：Master模式，用来作为端口发送消息，产生SCK并发送数据
- **从机**：Slave模式。用来作为端口接收消息，等待外部SCK并接收数据

## 💨快速开始

### 1. 环境准备

- **软件**：Keil MDK-ARM 5.36+
- **硬件**：STM32F407VET6核心板+ST7789屏（含FT6336触摸）

### 2. 编译与下载

1. 打开MDK-ARM/ST7789.uvprojx
3. 编译（F7）→下载（F8）→复位运行

### 3. 验证

1. 上电后屏幕出现Navert主界面，八个按钮对应八个端口，下面Config配置接收配置，CAN1配置为环回模式
2. 串口助手接USART1，进USART1页面→Forward to:选 CAN1→Start Forward
3. 串口助手发0x01→屏幕上出现From: USART1的数据，收到一帧0x01的数据
4. 返回进入CAN1界面，屏幕上出现From：CAN1的数据，收到一帧0x01的数据

详细步骤见 [Doc/STEP.md](Doc/STEP.md)。
